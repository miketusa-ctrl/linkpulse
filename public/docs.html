LinkPulse API docs

One call checks one page. LinkPulse fetches the page, pulls out its links, and checks up to 200 of them, following every redirect hop by hand. Before every request, the host's DNS records are checked to make sure it's a public address. It returns versioned JSON. Free, no key, CORS enabled.

Endpoints

Method & pathDescription
GET /api/check?url=<page>Check one page. Optional assets=false (only <a>/<area> links) and max=1..200 (links to fetch, default 200). When there are more links than max, about half the slots go to hyperlinks and half to assets, each in document order.
POST /api/checkSame, with a JSON body {"url": "...", "assets": true, "max": 200} (or form-encoded). The body can be at most 8 KB.
GET /api/healthService status, version, schema id and limits.
OPTIONS /api/*CORS preflight (Access-Control-Allow-Origin: *).

A URL without a scheme is treated as https://. Only http/https on ports 80/443 are accepted.

Examples

curl

curl -s "{{ORIGIN}}/api/check?url=https://example.com/" | jq '.summary'

# only <a href> links, at most 20
curl -s "{{ORIGIN}}/api/check?url=https://example.com/&assets=false&max=20"

# POST JSON
curl -s -X POST "{{ORIGIN}}/api/check" -H 'content-type: application/json' \
  -d '{"url":"https://example.com/"}' | jq '.links[] | select(.category=="broken") | .url'

JavaScript (browser or Node 18+)

const res = await fetch("{{ORIGIN}}/api/check?url=" + encodeURIComponent("https://example.com/"));
if (res.status === 429) {
  console.log("rate limited, retry after", res.headers.get("retry-after"), "s");
} else {
  const r = await res.json();
  if (r.error) throw new Error(r.error.code + ": " + r.error.message);
  console.log(r.summary);                                   // { checked, ok, broken, ... }
  for (const l of r.links.filter(l => l.category === "broken")) console.log(l.status, l.url);
  for (const l of r.links.filter(l => l.redirects)) console.log(l.hops.map(h => h.status + " " + h.url).join(" -> "));
}

Link object

{
  "url": "http://example.org/old",     // absolute URL as found on the page (fragment removed)
  "kind": "link",                       // link | image | script | stylesheet | icon | resource | iframe | media | embed
  "tag": "a", "count": 2,               // source tag; how many times it appears
  "category": "redirect",               // ok | redirect | broken | blocked | unchecked
  "status": 200,                        // final HTTP status (null if no response)
  "finalUrl": "https://example.org/new",
  "method": "HEAD",                     // HEAD, or GET when HEAD failed and was retried
  "redirects": 2,
  "hops": [ { "url": "http://example.org/old", "status": 301, "location": "https://example.org/old", "ms": 30, "method": "HEAD" },
            { "url": "https://example.org/old", "status": 302, "location": "https://example.org/new", "ms": 41, "method": "HEAD" },
            { "url": "https://example.org/new", "status": 200, "ms": 38, "method": "HEAD" } ],
  "ms": 112,
  "error": null,                        // or { "code": "...", "message": "..." }
  "flags": ["insecure_link"]
}
categoryMeaning
ok2xx/3xx final response with no redirects.
redirectEnds in a non-error response after one or more redirects (see hops).
brokenFinal status ≥ 400 (or 530). Also a host that doesn't exist (NXDOMAIN or no A/AAAA records, error.code: "dns_error"), a connect/TLS error, a timeout, a redirect loop, more than 10 redirects, or an invalid Location header.
blockedThe link or one of its redirect hops points somewhere LinkPulse refuses to fetch: a private/loopback/metadata IP, a hostname whose DNS answers include such an IP, a local name, a non-80/443 port, or credentials in the URL. Not fetched.
uncheckedNot fetched because the 1,000-request budget or the 45 s time limit ran out (error.code subrequest_budget / deadline), or because the DNS safety lookup failed (dns_check_failed, so the link was not fetched). Links beyond max are counted in notChecked. They're only listed in links (error.code: "link_cap") when the HTML alone shows mixed content or a plain-HTTP link.
flagMeaning
mixed_content_activeHTTPS page loads an http:// script, stylesheet, iframe, embed or other <link> resource. Browsers block these.
mixed_content_passiveHTTPS page loads an http:// image, video, audio or track.
insecure_linkHTTPS page has a plain http:// hyperlink.
https_downgradeA redirect hop goes from https to http.
long_chain3 or more redirects.
redirect_loop / too_many_redirectsLoop detected, or more than 10 hops.
maybe_bot_blockedFinal 401/403/429/999 or a Cloudflare cf-mitigated challenge. The link may work in a browser, since many sites block cloud IPs.
head_not_supportedHEAD returned an error but GET worked.
blocked_redirectA redirect pointed to a blocked target and was not followed.
resolves_privateThe link's host, or a redirect target's host, is a public name whose DNS answers include a private, loopback, link-local or metadata address (e.g. localhost.direct → 127.0.0.1).
get_fallback_skippedHEAD failed and no budget was left for a GET retry, so the HEAD result is shown.

Errors and rate limits

Errors return a non-2xx status with {"error": {"code", "message", ...}, "version"}.

HTTPcodeWhen
400invalid_url, invalid_scheme, credentials_in_url, invalid_requestBad input
403blocked_target, blocked_port, blocked_redirectThe page URL, or one of the page's redirect hops, is not a public 80/443 target. For the page, the host's A/AAAA records are also checked with DNS-over-HTTPS.
422dns_not_foundThe page host doesn't resolve.
429rate_limitedOver 20 checks/hour/IP (error.scope: "ip"), a short burst of more than ~10 per minute ("burst"), or the service-wide daily check capacity is used up ("global", resets 00:00 UTC). Has a Retry-After header (seconds) and error.retryAfterSec.
502/504page_fetch_failed, page_timeout, redirect_loop, too_many_redirects, bad_redirect, dns_errorThe page itself couldn't be fetched. error.redirects holds the hops so far.

Successful checks include X-RateLimit-Limit, X-RateLimit-Remaining and X-RateLimit-Reset (seconds). Identical requests within about 2 minutes are served from an in-memory cache (x-cache: HIT) and don't count. Inputs rejected by the URL rules before anything is fetched (400/403: scheme, port, IP literal, local names) don't count either. A page whose host fails the DNS check does count. A page that returns 4xx/5xx still gives a 200 response, with page.ok: false, and its links are not checked.

API keys: not available yet. If you send an X-Api-Key or Authorization header, it is ignored, the anonymous limit applies, and a note says so. There's no paid plan.

MCP server (for AI agents)

POST {{ORIGIN}}/mcp is a remote Model Context Protocol server (Streamable HTTP, stateless, JSON responses; protocol 2026-07-28 and the older initialize-based versions). It has one read-only tool, check_links (url, optional assets and max), which runs the same check as /api/check with the same limits: each call counts as one check. The tool returns the summary counts plus up to 25 problem links; use the JSON API for the full links[] list. Errors (blocked targets, rate limits) come back as tool results with isError: true and _meta["linkpulse/error"] = {code, httpStatus, retryAfterSeconds}.

{ "mcpServers": { "linkpulse": { "type": "http", "url": "{{ORIGIN}}/mcp" } } }

How targets are restricted (SSRF guard)

  • Only http:/https:, ports 80/443, no user:pass@.
  • IP literals in private, loopback, link-local, CGNAT, multicast, documentation or reserved ranges are refused. So are cloud metadata addresses (169.254.169.254, 100.100.100.200, fd00:ec2::254, 168.63.129.16), in IPv4 and IPv6 form, including IPv4-mapped, NAT64 and 6to4 forms. Decimal, hex and octal encodings (2130706433, 0x7f000001, 0177.0.0.1, 127.1) are normalized first.
  • localhost, *.local, *.internal, *.localhost, other special-use names, single-label hosts, wildcard-DNS services such as *.nip.io/*.sslip.io, and LinkPulse's own host are refused.
  • Every redirect hop is checked again before it's fetched.
  • DNS check on every request: Workers have no DNS API, so before each request (the page, every link and every redirect hop) LinkPulse looks up the host's A and AAAA records over DNS-over-HTTPS (Cloudflare, falling back to Google). If any answer is non-public, the request isn't made. Lookups are cached per host for one check only. If the lookup fails, the link is reported unchecked and not fetched.
  • Remaining limitation: DNS can change between our lookup and Cloudflare's own resolution at fetch time (DNS rebinding with a very short TTL). Cloudflare's network is a second layer here: outbound fetch() leaves from Cloudflare's edge, not from a private network. That's defense in depth, not a guarantee.
